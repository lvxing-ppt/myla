## 一、项目概述

MLMS 是一款面向中国临床微生物实验室的**中间件平台软件**，核心使命是连接实验室检验仪器、医院 LIS 系统和临床用户，实现微生物检验数据的自动采集、智能规则判读、分级审核管理和专业报告输出。

**对标产品：** bioMérieux MLMS / MAESTRIA（法国生物梅里埃，全球装机量最大的微生物中间件）

**市场定位：** 国产替代，适配中国医院环境和国产仪器生态

**注册目标：** NMPA 三类医疗器械软件

## 二、市场背景

### 2.1 临床微生物实验室现状

| 痛点 | 说明 |
|------|------|
| 数据孤岛 | 每台仪器独立工作站，数据不互通，手工誊抄到 LIS |
| 人工判读 | 药敏结果靠人工查 CLSI 手册判断 S/I/R，效率低易出错 |
| 审核效率低 | 无分级审核机制，主任和技师混在一起 |
| 危急值延迟 | 血培养阳性等紧急结果靠电话通知，无系统级闭环 |
| 报告单一 | 只能打印仪器自带报告，无法汇总多台仪器数据 |
| 进口垄断 | MLMS 价格昂贵（百万级），未适配国产仪器 |

### 2.2 市场规模

| 指标 | 数据 |
|------|------|
| 中国三级医院 | ~3,000 家 |
| 二级医院 | ~10,000 家 |
| 已有微生物实验室的医院 | ~5,000 家 |
| 进口中间件覆盖率 | <5%（仅大型三甲） |
| 国产中间件 | 几乎空白 |

### 2.3 竞争格局

| 产品 | 厂商 | 优势 | 劣势 |
|------|------|------|------|
| MLMS/MAESTRIA | bioMérieux | 功能完整、全球化、50+种仪器 | 价格高（百万级）、不支持国产仪器、本地化弱 |
| BD EpiCenter | BD | 与 Phoenix 仪器深度绑定 | 仅支持 BD 仪器 |
| WHONET | WHO | 免费、全球耐药监测 | 不是中间件，无实时采集 |
| **MLMS** | 我们 | 架构灵活、适配国产仪器、成本可控 | 新产品、需 NMPA 注册 |

## 三、技术架构

### 3.1 总体架构

```
┌─────────────────────────────────────────────┐
│            前端展示层 (Vue 3)                 │
│   工作台 │ 样本管理 │ 结果审核 │ 仪器监控 │ 报告 │
├─────────────────────────────────────────────┤
│          业务服务层 (Spring Boot)             │
│   样本管理 │ 结果管理 │ 工作流引擎 │ 报告引擎    │
│   权限认证 │ LIS 对接 │ 消息通知              │
├─────────────────────────────────────────────┤
│      仪器集成层 (SPI 插件框架)                 │
│   Channel → Splitter → Parser → Driver       │
│   InstrumentHub + 动态注册 + 设备监控          │
├─────────────────────────────────────────────┤
│        通信层 (TCP/File/Netty)                │
│         ASTM / HL7 / JSON / 私有协议           │
├─────────────────────────────────────────────┤
│    基础设施: MySQL + Redis + RabbitMQ          │
└─────────────────────────────────────────────┘
```

### 3.2 核心技术特性

| 特性 | 说明 |
|------|------|
| SPI 插件架构 | Channel×Splitter×Parser 三层解耦，新仪器只需实现 Parser |
| 动态注册 | API 注册仪器 → 热加载，无需重启 |
| 数据可靠性 | SHA-256 幂等去重 + ASTM ACK/NAK + 事务持久化 + MQ outbox 补发 |
| CLSI 规则引擎 | MVEL 表达式 + 天然耐药自动修正 + 危急值告警 |
| 三级审核 | TECHNICIAN→REVIEWER→DIRECTOR 角色+状态机 |
| 仪器监控 | 数据心跳 + @Scheduled 离线检测 + 管理 API |
| 模块化 | 12 个 Maven 模块，严格单向依赖 |

### 3.3 技术栈

| 层面 | 选型 | 版本 |
|------|------|------|
| 语言 | Java | 17 |
| 框架 | Spring Boot | 3.2.1 |
| ORM | MyBatis-Plus | 3.5.5 |
| 数据库 | MySQL | 8.0 |
| 缓存 | Redis | 7.x |
| 消息队列 | RabbitMQ | 3.x |
| 规则引擎 | MVEL | 2.5.2 |
| 报告 | Apache POI | 5.2.5 |
| 前端 | Vue 3 + Element Plus | — |

## 六、商业计划

### 6.1 路线图

```
一期（当前，95%）
  → 核心引擎 + 单仪器 + 审核 + 报告
  → 产品可用，开始内部试用

二期（8个月）
  → 前端7页面 + LIS HL7对接 + 质控 + 5+仪器
  → 可部署到医院试运行

三期（6个月）
  → Antibiogram + MDRO + TAT + NMPA 注册
  → 正式商业发布
```

### 6.2 竞争优势

| 优势 | 说明 |
|------|------|
| **国产化** | 适配国产仪器（安图/迪尔/鑫科），进口产品不支持 |
| **成本优势** | 价格约为 MLMS 的 1/10 ~ 1/5 |
| **灵活部署** | 纯软件，无硬件绑定，支持私有化部署 |
| **架构先进** | SPI 插件架构，接新仪器 = 写一个 Parser（约 80 行） |
| **本地服务** | 中文界面 + 中文文档 + 国内技术支持 |

### 6.3 商业模式

| 模式 | 说明 |
|------|------|
| 软件授权 | 按仪器数量 / 按年授权 |
| 实施服务 | LIS 对接 + 仪器适配 + 部署培训 |
| 运维服务 | 远程运维 + 升级 + 7×24 支持 |
